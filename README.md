# WebArchive

## Авторизация

Кнопка `[ ENTER ]` открывает окно `SYSTEM_LOGIN.exe`. Для первого входа нажмите `Registration`, укажите логин (3–32 латинских символа, цифры, `.`, `_`, `-`) и пароль (8–128 символов). После регистрации вход выполняется автоматически. Кнопка `[ ENTER ]` скрывается, выход доступен в `PROFILE` → `[ LOG OUT ]`.

Аккаунты и сессии хранятся в PostgreSQL. При запуске бэкенд выполняет идемпотентную миграцию `BackEnd/migrations/001-auth.sql`: существующие игры и данные сохраняются. Пароли хешируются scrypt с индивидуальной солью; сервер хранит только хеши токенов сессий. HttpOnly-cookie действует 7 дней; в production она передаётся только через HTTPS. Выход удаляет сессию на сервере. Для входа и регистрации действует ограничение 20 запросов за 15 минут на IP; запросы с другого Origin отклоняются.

Восстановление пароля по электронной почте пока не реализовано; кнопка `Forgot password?` показывает справку. Права администратора пока не реализованы.

## Общий чат и страницы игр

CHAT_VOID открывает единый чат. Кнопка «Картинка / GIF» прикрепляет изображение до 2 МБ с предпросмотром; его можно отправить с текстом или отдельно. Двоичные файлы загружаются HTTP-запросом, WebSocket передаёт метаданные и ссылку на изображение. История хранится в PostgreSQL; новые сообщения приходят через WebSocket `/ws/chat` (WSS за nginx), с автоматическим переподключением и загрузкой пропущенных сообщений по ID. Отправка и история используют HTTP API `/api/chat`. Фильтров слов, жалоб и модераторских функций нет. Читать могут гости, писать — вошедшие пользователи. Enter отправляет сообщение, Shift+Enter добавляет строку. Сообщение — до 2000 символов, старую историю можно подгрузить.

У каждой игры отдельные комментарии и оценки от 1 до 5. Пользователь имеет один голос на игру, повторный выбор меняет его оценку. Среднее и количество голосов рассчитываются по реальным записям; рейтинг карточек каталога использует те же данные вместо демонстрационных оценок. Гости могут читать комментарии, писать и голосовать можно после входа.

Кнопка «Скачать SWF» скачивает оригинальный файл через `/api/games/ID/download` с заголовком attachment. Счётчик увеличивается после успешной отправки файла; загрузка игры в Ruffle скачиванием не считается. Данные сообщества создаёт идемпотентная миграция `003-community.sql`. Для WebSocket в nginx настроены Upgrade и heartbeat; Vite также проксирует `/ws` при разработке. Изменяющие HTTP-запросы проверяют сессию и Origin; есть техническое ограничение частоты запросов, без модерации содержимого.

## Профиль и стена

Кнопка PROFILE открывает собственную страницу `/profile/ID`. Кнопка «Редактировать профиль» позволяет изменить аватар, ник и био. Логин для входа не меняется. Ник — до 40 символов, био — до 1000. Страна и почта не запрашиваются. Ссылку на публичный профиль можно скопировать кнопкой «Ссылка».

Читать стену могут все посетители; оставлять текстовые записи и изображения — авторизованные пользователи. Запись ограничена 2000 символами. Автор может удалить свою запись, владелец профиля — любую запись на своей стене. Старые записи подгружаются кнопкой «Показать ещё» (по 20 записей).

Аватарки и вложения: PNG, JPEG, WebP или GIF до 2 МБ и 16 мегапикселей. Сервер декодирует их и сохраняет в PostgreSQL как WebP: аватар статичный до 256×256, вложение до 1280×1280. Новые GIF на стене и в чате сохраняют анимацию (до 200 кадров, суммарно до 32 мегапикселей). Старые GIF, ранее сохранённые статичными, автоматически восстановить нельзя. Миграция `002-profiles.sql` выполняется при запуске бэкенда и сохраняет существующие аккаунты. Для изменяющих запросов проверяются сессия, Origin и права владельца; действует лимит 15 действий в минуту на IP.

Проверки: `cd BackEnd; npm test` и `cd FrontEnd; npm test`. В GitHub Actions тесты обеих частей выполняются до сборки образов.

Для практической работы №18 используйте [инструкцию локального деплоя](deploy/README.md):

```powershell
cd deploy
docker compose up --build -d
```

Предварительная настройка пароля и сертификата описана в инструкции. Адрес: https://webarchive.localhost.
Конфигурация в `deploy/` запускает фронтенд, Express API, PostgreSQL и nginx с HTTPS.
Корневой `docker-compose.yml` ниже относится к прежнему запуску только фронтенда.

Кусочек старого интернета: каталог флеш-игр с поиском, пагинацией и фильтрами,
а также общий чат. Проект стилизован под интерфейсы старых настольных систем.

## Стек

- **Фронтенд:** React 18, Vite, Tailwind CSS v4
- **Тесты:** Vitest, React Testing Library
- **Контейнеризация:** Docker, Docker Compose, nginx
- **CI/CD:** GitHub Actions → GitHub Container Registry (ghcr.io)
